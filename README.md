# 電車最速バトル動画ジェネレーター (train-route-race-video-kansai)

「A駅からB駅まで、どの交通手段が一番速いか」を比較する縦動画
(1080x1920, ショート動画向け)を自動生成するツールです。地図上で複数の
経路が実際のルート形状に沿ってレースし、通過駅ポップアップ・スコア
ボード・競馬実況風のテロップ、実況台本(.txt / .srt)まで一括で作ります。

もともとは関西圏の私鉄・JR路線データ(GeoJSON/駅データSHP、JR西日本・
阪急・阪神・京阪・近鉄・南海・Osaka Metro 計40路線)を使った「大阪→京都
どっちが早い」動画のためのツールでしたが、現在は **日本全国** の
新幹線・在来線特急・飛行機・地上交通を組み合わせた「東京→札幌、新幹線
vs 飛行機」のような対決動画にも対応しています。`configs/*.json` を
書けば(あるいは後述のconfigビルダーを使えば)**どの2地点・どの交通手段
の組み合わせでも**汎用的に使えるように設計してあります。

## できること

- 実在の路線形状(GeoJSON)に沿って複数の経路をレースさせるアニメーション
- 全国版(`map_extent: "japan"`)では日本全体の海岸線を背景に表示、
  関西版(デフォルト)では関西圏の路線図を背景に表示
- 車両アイコンは回転しない(独自イラストへの差し替え可能)。飛行機・
  鉄道・バス・徒歩・モノレール等、区間(leg)ごとにアイコンを選択可能
- 主要駅を通過すると「大きく→通常サイズ」でポップアップ表示
- 下部にスコアボード(進捗バー・経過分数)
- 競馬実況風のテロップをテンプレートから自動生成し、動画に焼き込み
- 実況の台本(.txt)と字幕(.srt)を別ファイルでも出力
- 駅データ(SHP)の品質チェックツール付き(後述の「既知の注意点」を参照)

### 全国版(新幹線・在来線特急・飛行機)の対応範囲

- **新幹線**: 東海道・山陽・九州新幹線、東北・北海道新幹線、上越新幹線、
  北陸新幹線の4系統をカバー
- **在来線特急**: うずしお・しおかぜ・やくも・はくと・ソニック・にちりん・
  リレーかもめ・おき・北斗の実ルート(実際の線形)に対応
- **到着地**: 47都道府県庁所在地すべてから選択可能。新幹線が直接通る駅は
  そのまま、在来線特急で接続する県庁所在地は実ルートで、それ以外は
  最寄りの新幹線駅からの直線区間で自動的に経路を組み立て
- **飛行機**: 出発・到着空港を選んで大圏経路(great circle)でレース。
  空港と都心を結ぶ地上交通(バス・鉄道)区間もあわせて生成
- **乗換**: 乗換駅の到着時刻・発車時刻をそれぞれ入力すると、その差分が
  「待ち時間」として動画に反映される
- **通過駅**: 停車せず通過するだけの駅も、時刻を指定して経路上に表示可能

## セットアップ

```bash
git clone <このリポジトリのURL>
cd train-route-race-video-kansai

# Python依存パッケージ
pip install -r requirements.txt

# ffmpeg(動画エンコードに必須。pipには無いのでOS側で入れる)
sudo apt-get update && sudo apt-get install -y ffmpeg

# 日本語フォント(Noto Sans CJK)
sudo apt-get install -y fonts-noto-cjk
```

macOSの場合は `brew install ffmpeg` と、日本語フォントは標準搭載のものが
自動的に見つからない場合、`race_video/fonts.py` の `_CANDIDATE_DIRS` に
パスを足すか、環境変数 `RACE_VIDEO_FONT_DIR` でフォントの入っている
ディレクトリを指定してください。

## 使い方

```bash
# 動画生成(30fps, フル画質)
python3 -m race_video.cli configs/osaka_kyoto.json

# 低fpsの高速プレビュー(内容確認用、10fps)
python3 -m race_video.cli configs/osaka_kyoto.json --fast

# 駅データSHPの品質だけチェックしたいとき
python3 -m race_video.cli configs/osaka_kyoto.json --check-stations

# 全国版(新幹線 vs 飛行機、legsモード)の例
python3 -m race_video.cli configs/tokyo_fukuoka_plane_vs_shinkansen.json
```

`--geojson` / `--shp` のデフォルトはこのリポジトリの関西データ
(`data/routes.geojson` / `data/stations_shp/kansai_stations`)を指す
ようになっているので、通常はオプション指定なしでそのまま使えます。
`configs/tokyo_fukuoka_plane_vs_shinkansen.json` のような legsモード
(後述)のconfigでは駅データSHPを使わないため、これらのオプションは
自動的に無視されます。

生成物は `output/` に出力されます:

- `output/<slug>.mp4` … 完成動画
- `output/<slug>_base_map.png` … 背景マップ単体(確認用)
- `output/<slug>_commentary.txt` … 実況台本(タイムコード付き)
- `output/<slug>_commentary.srt` … 字幕ファイル

## 他のルートを追加する方法(汎用化のポイント)

新しい比較動画を作るには `configs/` に新しいJSONを1つ足すだけです。
`configs/osaka_kyoto.json` をコピーして書き換えてください。

```jsonc
{
  "slug": "umeda_sannomiya",                // 出力ファイル名に使われる
  "title_line1": "大阪梅田 → 神戸三宮",
  "title_line2": "どっちが早い!? 電車最速バトル",
  "start_name": "大阪梅田",
  "end_label": "神戸三宮",
  "compress_sec_per_min": 0.5,              // 実1分を動画何秒に圧縮するか
  "intro_sec": 2.0,
  "outro_hold_sec": 4.0,
  "routes": [
    {
      "key": "route_a",                     // ルートを識別するキー(a/bなど)
      "name": "阪神本線(直通特急)",
      "short_name": "阪神特急",
      "color": [230, 20, 20],
      "icon_path": "assets/hanshin_icon.png", // 省略可(無ければ簡易アイコン)
      "stations": [
        {"line": "阪神本線", "name": "大阪梅田", "t_min": 0,  "popup": true},
        {"line": "阪神本線", "name": "尼崎", "t_min": 8, "popup": true},
        {"line": "阪神本線", "name": "神戸三宮", "t_min": 27, "popup": true}
      ]
    },
    { "key": "route_b", "name": "...", "stations": [ ... ] }
  ]
}
```

駅の「並び順」は `stations` 配列の順番がそのまま使われます。`line` には
駅データSHPの `line_name` と完全一致する路線名を指定してください
(一致しないとエラーで教えてくれます)。`t_min` は始発駅からの累積所要時間
(分)で、乗換案内サイト等の実データを参考に入れてください。

途中で別の路線に乗り換える(直通運転含む)場合は、単に `stations` の
`line` を次の駅から新しい路線名に変えるだけです。乗換駅には
`"transfer": true, "transfer_note": "..."` を、乗換なしの直通運転駅には
`"direct_through": true, "transfer_note": "..."` を付けると、実況テロップの
文面が変わります。

`popup: true` を付けた駅だけが動画中にポップアップ表示され、実況の
対象にもなります(あまり多いと画面が窮屈になるので、主要駅だけ絞るのが
おすすめです)。

上記は駅名ベース(関西版)のconfig形式です。全国版(新幹線 vs 飛行機など)
のように、駅データSHPに無い地点(空港・在来線特急の実ルート・任意の
座標など)を組み合わせたい場合は、次の「legsモード」を使います。

### legsモード(全国版・座標ベースの汎用フォーマット)

`"routes[].mode": "legs"` を指定すると、駅データSHPを使わず、
`legs` 配列に列挙した区間(leg)を順番につないで経路を組み立てます。
各leg は以下のいずれかの `kind` を持ちます。

- `"coords"` … 実際の路線・道路形状に沿った座標列(`coords: [[lon,lat],...]`)
  をそのまま経路として使う(新幹線・在来線特急の実ルートなど)
- `"straight"` … 2点間を直線で結ぶ(最寄り駅から目的地までの概算区間など)
- `"great_circle"` … 2点間を大圏経路で結ぶ(飛行機区間)
- `"wait"` … 移動せずその場に留まる(乗換の待ち時間など)

各legには `icon`(`train`/`plane`/`bus`/`walk`/`monorail`等)、
`t_start`/`t_end`(動画の共有タイムライン上の分数)、`label`・`popup`
(ポップアップ表示するか)を指定できます。

地図上を実際に動くのは小さなドットのみで、ドットから引き出し線が伸び、
その先にアイコン画像(電車・飛行機・待機中・バス・モノレール等)だけが
表示されます(この仕組みは legsモード・従来モードの両方に共通)。複数
ルートが同じ地点(レース開始直後など)にいてもアイコン同士が重ならない
よう、引き出し線の向き・長さはルートごとに自動でずらしています。

現在の状態を示すステータス文言(「搭乗待ち」「鉄道移動中」など)は地図上
には出さず、下部スコアボードの交通手段名とプログレスバーの間に、アイコン
と並べて常時表示します(「搭乗待ち」のような `kind: "wait"` のlegは
`label` の文言をそのまま、それ以外の移動区間は `icon` に応じた既定の
文言 ― 「鉄道移動中」「飛行中」「バス移動中」「徒歩移動中」
「モノレール移動中」― を自動で表示します)。到着後は表示されなくなります。
駅データSHPベースの従来モード(`"mode"` 未指定)のルートは、ステータス
文言は表示されず、スコアボードにはアイコンのみ表示されます。

`map_extent: "japan"` を
configのトップレベルに指定すると、背景地図が関西圏ではなく日本全国の
海岸線(`data/coastline_japan.geojson`)になり、かつ**出発地・到着地・
経路がちょうど画角に収まるように、動画ごとに自動でズームレベルが
計算されます**。方角(北が上)・実際の形は変えず(回転や引き伸ばしは
しません)、縦横比を保ったまま出発地・到着地の周辺にズームします。

東京〜福岡・東京〜広島のように出発地・到着地がほぼ東西一直線に並ぶ
組み合わせは、縦長(1080x1920)キャンバスとは向きが直交するため、
縦横比を保つ以上、上下にある程度の余白が残ります。ただしその余白に
北海道・東北・沖縄など無関係な地形が写り込まないよう、**出発地・
到着地の周辺だけを描画対象にして**います(遠く離れた地域は最初から
描かれません)。東京〜札幌のようにもともと縦方向のペアは、この余白は
ほとんど発生しません。日本全体を常に同じ縮尺で表示したい場合は、
代わりに `map_extent: "japan_fixed"` を指定してください(出発地・
到着地が近い/遠いに関わらず、常に北海道〜沖縄までの固定範囲で表示
されます)。

このモードのconfigは手で書くよりも、前述の全国版ビルダーで組み立てて
書き出すことを想定しています(`configs/tokyo_fukuoka_plane_vs_shinkansen.json`
がビルダー出力の実例です)。

## configを手入力で作るツール(configビルダー)

`configs/*.json` を手で書く代わりに、Claude Artifactとして公開している
GUIツールでルートを組み立てられます。2種類のビルダーがあります。

### 全国版(飛行機 vs 鉄道 レースビルダー)

https://claude.ai/artifact/EDU1vFaX1qQriS4FJgS4FJ

「東京→札幌、新幹線 vs 飛行機」のような全国スケールの対決動画のconfigを
作れるビルダーです。

- 出発地(空港・新幹線区間の起点)と到着地(47都道府県庁所在地)を
  それぞれ上部のセレクトボックスから選ぶだけで、新幹線ルート・在来線
  特急ルート・空港区間・地上交通区間が自動的に組み立てられる
- 経由駅・通過駅を追加して時刻を個別入力可能。乗換駅は到着時刻と
  発車時刻を別々に入力すると、その待ち時間が自動的に動画に反映される
- 区間(leg)ごとに鉄道・飛行機・バス・徒歩などのアイコンを選択可能
- 「JSONを保存」で `configs/<slug>.json` として使えるファイルを書き出し
  (`configs/tokyo_fukuoka_plane_vs_shinkansen.json` が出力例)

このビルダーが出力するconfigは `"mode": "legs"` 形式で、駅データSHPを
使わず地図上の座標(lon/lat)を直接指定する汎用フォーマットです。

### 関西版(駅レースビルダー)

関西圏の私鉄・JR路線データ(`data/routes.geojson` /
`data/stations_shp/`)を使った、駅名ベースの経路(`"mode"` 未指定、
通常のconfig形式)を作るビルダーです。

- ルートごとに路線区間を追加(通常の路線は始点駅・終点駅を選ぶだけ、
  大阪環状線のような駅の並び順が一意に決まらない路線は、あらかじめ
  用意された系統プリセットから範囲選択するか、駅を1つずつ選ぶ手動モードに
  自動で切り替わります)
- 組み立てた駅の一覧から、動画にポップアップ表示したい駅にチェック
- 各駅までの所要時間(分)を手入力(乗換案内サイト等で調べた実データを想定)
- 乗換駅・直通運転駅にはメモを添えられる
- 「JSONを保存」でそのまま `configs/<slug>.json` として使えるファイルを
  書き出し(保存に失敗する環境ではクリップボードへコピーします)

開いた時点で大阪→京都の例が読み込まれた状態になっているので、まずは
それを編集しながら使い方を確認してみてください。入力内容はブラウザの
localStorageに自動保存されるので、リロードしても失われません
(「サンプルに戻す」で大阪→京都の例にリセットできます)。

## 経路データのクリーニングについて

`routes.geojson` には、複数の物理経路をデータ生成時に結合した際の
継ぎ目と見られる「同じ地点を一瞬だけ往復してしまう」重複区間が、ごく
一部の路線に混入することがあります。放置すると
動画中で車両アイコンが一瞬だけ後ろに戻って見えてしまうため、
`race_video/route_builder.py` の `remove_backtracking()` が、経路を
組み立てるたびに自動でこの種の重複・孤立ノイズ頂点を取り除きます
(本物の急カーブは区別して残します)。特定の路線に対する特別扱いでは
なく、どの区間を組み合わせても同じロジックが適用されます。

## 「大阪環状線」のようなループ路線について

大阪環状線は始発・終着が同じ駅(大阪)に戻ってくる環状運転のため、
「駅の並び順」だけでは向き・区間が一意に決まりません。そのため
`race_video/route_builder.py` の `LOOP_LINES` にこの路線を登録して、
経路のノイズ除去ロジック(`collapse_revisits`。本来は同一地点を一瞬だけ
往復してしまうデータ上のノイズを畳み込むためのもの)が環状区間そのものを
誤って削ってしまわないようにしています。

config の `"line"` に `"大阪環状線"` を使う場合は、他の路線のように
始点駅・終点駅だけを指定するのではなく、`stations` 配列に実際に停車する
順番をすべて明示的に書いてください(`configs/` のサンプルや、駅レース
ビルダー側の系統プリセットが実例です)。それ以外の39路線は駅の並び順が
一意に決まる通常の路線なので、始点駅・終点駅を指定するだけで間の駅が
自動的に埋まります。

## 途中駅の所要時間(t_min)を空欄にする

停車・乗換をしない単なる通過駅は、config の `t_min` を `null`(または
キーそのものを省略)にしてかまいません。`route_builder.py` が、実際に
組み立てた経路上の距離(km)に比例させて自動的に補完します。ただし
「最初の駅」と「最後の駅」の `t_min` は自動補完できないため、必ず数値を
入れてください(省略するとエラーになります)。config builder(駅レース
ビルダー)側でも、途中駅の所要時間欄は空欄のままで生成できます。

## データについて

- `data/routes.geojson` … 関西40路線(JR西日本・阪急・阪神・京阪・近鉄・
  南海・Osaka Metro)の線形状(LineString/MultiLineString)。関西版
  (駅名ベース)のconfigでのみ使用
- `data/stations_shp/kansai_stations.*` … 40路線分の駅データ(Shapefile。
  フィールドは `line_name, stn_name, seq, cum_km, color`)。関西版のみ使用
- `data/coastline.geojson` … 関西版の背景マップ用の海岸線データ
- `data/coastline_japan.geojson` … 全国版(`map_extent: "japan"`)の
  背景マップ用の日本全国の海岸線データ。国土数値情報(行政区域データ
  N03)から抽出・簡略化したもの

全国版の新幹線・在来線特急の実ルート座標、47都道府県庁所在地の座標、
空港座標などは、これらのデータファイルとしてではなく、全国版config
ビルダー(前述のArtifact)のJavaScript内に直接埋め込まれています。
ビルダーが出力するconfig(`"mode": "legs"`)には実際の座標列が literal
に書き出されるため、このリポジトリ側は生の地理データを持つ必要が
ありません。

### 既知の注意点(駅データSHPの品質)

`python3 -m race_video.cli <config> --check-stations` で全路線の品質を
チェックできます。関西40路線はいずれも駅の並び順(seq)・距離(cum_km)・
座標に問題は見つかっていません。唯一の例外は前述の大阪環状線で、これは
データの品質問題ではなく環状運転そのものの性質上、config側で停車順を
明示する必要がある、という点にご注意ください。

将来的にSHP生成スクリプト側を直すなら、「系統(LineStringのセグメント)
ごとに」駅を割り当て直す形にすると、この2路線も自動生成に使えるように
なるはずです。

## 車両アイコンについて

`icon_path` に透過PNG(進行方向=右向き推奨)を指定すると、その画像が
車両アイコンとして使われます。**回転はさせません**(要件どおり、常に
同じ向きで表示されます)。指定が無い場合は `race_video/animate.py` が
種別(電車/飛行機/待機中/バス/モノレール)ごとの簡易なプレースホルダー
アイコンを描画します。`assets/` に画像を置いてconfigから参照してください。

- **ルート全体の既定画像**: `configs/*.json` の各routeに直接 `icon_path`
  を指定すると、そのルートの電車アイコン(kind未指定/`"train"`のとき)に
  常に使われます(駅データSHPベースの従来モードで使えるのはこれだけです)。
- **leg単位の画像(legsモードのみ)**: `"mode": "legs"` の各leg
  に個別の `icon_path` を指定すると、そのleg区間だけ違う画像が使われ
  ます。乗り換えで実際の車両(路線)が変わる区間ごとに新幹線の車両
  画像を切り替えたり、飛行機の機体画像・バス(市内移動)のアイコン画像を
  個別に指定したりできます(`kind` が `train`/`plane`/`bus`/`walk`/
  `monorail`/`wait` のどれであっても使えます)。leg に `icon_path` が
  無いlegは、`kind` が `train`(または未指定)のときだけルート全体の
  既定 `icon_path` にフォールバックし、それ以外の種別(飛行機・バス等)
  でleg側に指定が無ければベクターのプレースホルダーになります。

```jsonc
{
  "legs": [
    {"kind": "coords", "coords": [...], "icon": "train",
     "icon_path": "assets/nozomi.png", "t_start": 0, "t_end": 40},
    {"kind": "coords", "coords": [...], "icon": "train",
     "icon_path": "assets/sakura.png",  // 乗り換え後は別画像
     "t_start": 40, "t_end": 90},
    {"kind": "great_circle", "from": [...], "to": [...], "icon": "plane",
     "icon_path": "assets/my_airplane.png", "t_start": 0, "t_end": 100},
    {"kind": "straight", "from": [...], "to": [...], "icon": "bus",
     "icon_path": "assets/city_bus.png", "t_start": 100, "t_end": 115}
  ]
}
```

`icon_path` には、上記のようなファイルパス(`assets/` 配下)のほか、
`"data:image/png;base64,...."` のような **data URI をそのまま**
指定することもできます。飛行機vs鉄道レースビルダー(HTML)の
「飛行中のアイコン画像」「市内移動のアイコン画像」で画像ファイルを
選ぶと、ブラウザにはファイルシステムが無いため、選んだ画像をこの
data URI形式で直接JSONに埋め込んで書き出します。`assets/` に画像を
置く必要はなく、書き出されたJSONをそのまま `configs/` に置いて
動画生成すれば、選んだ画像が該当のlegに使われます。

## ブラウザから動画生成を実行する(web/app.py)

おすすめの使い方: **JSON作成(駅レースビルダー)はスマホ含めどこからでも、
動画生成は自分のPCで** という役割分担です。駅レースビルダーはブラウザの
Claude Artifactとして動くので場所を選びませんが、動画生成はCPUを使う
重い処理なので、自分のPC(Renderの無料プランよりずっと速い)で実行する
ことをおすすめします。

```bash
pip install -r requirements.txt   # Flaskが追加されています
python3 web/app.py
# http://127.0.0.1:8080 を開く
```

「① JSONを用意して生成」では、駅レースビルダーからダウンロードした
JSONファイルを選ぶか、クリップボードに貼り付けるかたちで読み込めます。
「② 保存済みの設定から生成」では `configs/*.json` が一覧表示されます。
どちらも「生成する」を押すとバックグラウンドで
`python3 -m race_video.cli configs/<slug>.json` が実行されます。生成中は
数秒おきに状況をポーリングし、完了すると `output/` にできたmp4をそのまま
ブラウザからダウンロードできます。「低画質プレビュー(高速)」に
チェックを入れると `--fast` オプション(10fps)で素早く確認できます。

**出力ファイル名を指定する**: 「出力ファイル名(任意)」欄に入力すると、
configの `slug`(`configs/<slug>.json` という保存先ファイル名)とは
別に、好きな名前のmp4として出力できます(例: `新宿藤沢_対決版`)。
空欄なら従来通りslugがそのままファイル名になります。CLIから直接実行
する場合は `python3 -m race_video.cli configs/xxx.json --out-name 好きな名前`
のように指定します。

Dockerfileの `CMD` はデフォルトでこのWebページを起動するようになって
いるので、Renderなどにデプロイしてブラウザ経由で動画生成することも
引き続き可能です。ただし無料プランはCPU・メモリの制限が厳しいため、
基本的には自分のPCでの実行をおすすめします。

**生成中にサーバーが再起動してしまった場合について**: メモリ・CPUの
制限が厳しい環境(Renderの無料プランなど)では、生成中にプロセスごと
再起動されてしまうことがあります。この場合、以前は「エラー: not found」
という分かりにくい表示になっていましたが、現在は job_id と出力ファイル名
の対応をファイルに残しておき、(1) 出力ファイルがすでに完成していれば
自動的に「完成」扱いに復旧し、(2) 完成していなければ「サーバーが再起動
された可能性があります」という分かりやすいメッセージを表示するように
しています。それでも頻発する場合は、自分のPCで実行するか、
「低画質プレビュー(高速)」を使ってみてください。

## 実況テロップについて

`race_video/commentary.py` が実況台本(`output/<slug>_commentary.txt`)と
字幕ファイル(`output/<slug>_commentary.srt`)を常に生成しますが、動画
本編への焼き込み(テロップ表示)はデフォルトでは行いません。動画内に
テロップを表示したい場合は、configに `"show_captions": true` を追加して
ください。

## Renderへのデプロイ手順

1. このリポジトリをGitHubにpush(または本READMEにある手順でアップロード)
   しておく。
2. [Render](https://render.com)にログインし、ダッシュボードで
   「New +」→「Web Service」を選ぶ。
3. 連携したGitHubアカウントからこのリポジトリを選択する。
4. Runtimeを **Docker** にする(Render側で `Dockerfile` が自動検出され、
   `ffmpeg` ・ `fonts-noto-cjk` ・ Python依存パッケージが全部インストール
   される)。
5. プラン(Instance Type)は、試すだけなら **Free** で問題ありません。
   ただしFreeプランは15分アクセスが無いとスリープし、次のアクセス時に
   起動し直すので、久しぶりにアクセスすると最初の表示が少し遅くなります。
6. 「Create Web Service」でデプロイを開始する。ビルドに数分かかります。
7. 完了すると `https://<サービス名>.onrender.com` のようなURLが発行される
   ので、そこを開けば動画生成ページが表示されます。

**注意点**: Renderの無料プランのストレージはコンテナの再起動・再デプロイ
のたびにリセットされます(ディスクを追加していないため)。生成した動画は
その場でダウンロードしてください。もし複数人で使う・過去の動画も残して
おきたい、といった要件が出てきたら、Render の Web Service に永続ディスク
(Persistent Disk)を追加する、またはS3などの外部ストレージに保存する形に
拡張できます。

## 時間距離カルトグラム動画「近いのに遠い？遠いのに近い？〇〇からの距離」

起点の駅から各都道府県の代表駅への**方角はそのまま**、**距離だけを所要時間で**
描き直す縦動画(1080x1920)を作ります。基準は時速200km(1時間 = 200km)で、
これより速く行ける県は起点に近づき、遅い県は遠ざかります。

```bash
# 東京発・鉄道のみ
python3 -m race_video.cli configs/timecarto/tokyo_rail.json
# 福岡発・鉄道＋飛行機(10fpsの高速プレビュー)
python3 -m race_video.cli configs/timecarto/fukuoka_best.json --fast
```

- `configs/timecarto/` に 47都道府県 × `rail`(鉄道)/`best`(鉄道＋飛行機) の
  設定が入っています(沖縄の鉄道版は行ける県が無いので除外、計93本)。
- 背景の日本地図(`data/japan_land.geojson`、Natural Earth 1:10m・パブリックドメイン)は
  起点を中心とした正距方位図法で描くので、動く前の点(before)は地図上の実際の位置に重なります。
- 県番号順に1秒ごと(`gap_sec`)、1県ずつ線が「にゅっ」と伸び縮みし、効果音が鳴ります。
  音程が上がる「にゅ↑」は遠くなった、下がる「にゅ↓」は近くなったの合図です。
  ほとんど変化が無い県も小さく鳴ります。
- 動いた県には元の位置(○)から新しい位置(●)への点線が残るので、最後の数秒で
  before → after を一度に見比べられます。最後に「いちばん近く/遠くなった県」の名前を表示します
  (150km未満の近距離の県はこの比較から除外)。
- 画面下部に「都道府県｜判定結果」の表(4段組み)を出します。判定は5段階
  (指数120以上「近くなった」/105以上「少し近くなった」/95〜105「ほぼそのまま」/80以上「少し遠くなった」/80未満「遠くなった」)で、地図下のパネルや最後のまとめと同じ判定を使います。
  最後のまとめは、判定が「近くなった」県が無い起点では「いちばん速かった ○○」と表示します
  (鉄道版は200km/h基準だと近くなる県が無い起点が多いため、表と食い違わないようにしている)。
- タイトル・県名・表・凡例などの文字は、画面の左右端から60px以上内側に置きます。
  画面端に近い県は、点はそのままで文字だけ内側に寄せ、必要なら引き出し線で結びます。
- 出力: `output/<slug>.mp4`(音声付き)、`<slug>_final.png`(最終フレーム。サムネイル用)、
  `<slug>_base_map.png`、`<slug>_audio.wav`

### 設定JSON

Web版ツール(時間距離カルトグラム)の「所要時間」タブにある **縦動画用JSONをコピー** で、
画面で選んでいる起点・モード(所要時間の手入力による上書きも反映)の設定をそのまま作れます。
`web/app.py` の「貼り付けて生成」にもそのまま使えます。

| キー | 意味 |
|---|---|
| `type` | `"time_cartogram"` 固定(このキーで通常のレース動画と切り替わる) |
| `title_line1` / `title_line2` | タイトル2行(例: 「近いのに遠い？遠いのに近い？」「東京からの『時間距離』」) |
| `title_highlight` | 2行目で色を変える部分(既定 `『時間距離』`。鉄道版はオレンジ、鉄道＋飛行機版は青) |
| `gap_sec` | 1県ずつの間隔(秒)。既定1.0 |
| `move_sec` | 1県の線が伸び縮みする時間(秒)。既定0.6 |
| `intro_sec` / `outro_hold_sec` | 最初に実際の距離を見せる秒数 / 最後の before→after を見せる秒数 |
| `ring_hours` | 同心円の間隔(時間)。既定2(= 2時間 400km ごと)。円が詰まりすぎる時は自動で倍にする |
| `final_hold_sec` / `before_hold_sec` / `all_move_sec` | 最後の見せ場: 最後の県が動いてから待つ秒数(既定2) → before の地図を見せる秒数(既定1) → 全県いっせいに after へにゅるっと動く秒数(既定2)。この間は地図上の県名を出さない |
| `label_window` | 地図上の県名を出すのは、いま動く県の前後この数の県だけ(既定3。-1で全県) |
| `map_margin_px` | 背景の地図・同心円を描く範囲。県の点(before/after)の上下左右の最遠地からこの余白まで(既定40px)。それより外の陸地(石垣島・稚内など)はふわっと消す |
| `order` | `code`(県番号順) / `near`(近い順) / `far`(遠い順) |
| `origin` | 起点 `{pref, station, lat, lon}` |
| `destinations[]` | 行き先 `{pref, station, lat, lon, minutes, air, route}`。`minutes` が `null` の県は「行けない」扱い |

### 47都道府県ぶんをまとめて生成する(for文)

`tools/render_timecarto_all.py` が `configs/timecarto/` の設定を県番号順(北海道→沖縄)にループして、
まとめて書き出します。CPUコアを使って複数本を同時に生成します。

```bash
python3 tools/render_timecarto_all.py                      # 47都道府県 × 鉄道版・飛行機版(93本)
python3 tools/render_timecarto_all.py --mode best          # 鉄道＋飛行機版だけ(47本)
python3 tools/render_timecarto_all.py --mode rail          # 鉄道版だけ(46本。沖縄は除く)
python3 tools/render_timecarto_all.py --only tokyo,osaka   # 一部の県だけ
python3 tools/render_timecarto_all.py --workers 4 --skip-existing   # 並列数を指定・作成済みは飛ばす
python3 tools/render_timecarto_all.py --fast --zip output/timecarto_all.zip   # 確認用10fps・zipにまとめる
```

- 出力: `output/timecarto_<県>_<rail|best>.mp4` と、サムネイル用の最終フレーム `..._final.png`
- 目安: フル画質(30fps)で1本あたり約2分(1コア)。93本を4並列で約50分。
- Webページ(`web/app.py`)の「③ 時間距離カルトグラムを47都道府県まとめて生成」からも実行でき、
  完成するとzipでダウンロードできます。ただしRenderの無料プランではCPUが足りず途中で止まることが
  あるので、全県ぶんは自分のPCで実行するのがおすすめです。
